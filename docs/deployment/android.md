# Android

Built and released independently of the web SPA. A web deployment never requires a new binary; a mobile release never
requires a web deployment (unless a shared API contract change needs both).

## Local development

Prerequisites: Node 24, Android Studio (SDK, emulator), JDK 17+.

```bash
npm ci
cd apps/mobile
npx expo run:android           # Generate, build and install the native debug app on the emulator
```

From VS Code, run **Tasks: Run Task → mobile: Android emulator (native debug build)**. This connects to the running
MyVedicStar shared API on port 5289 using `http://10.0.2.2:5289/api/v1` inside the emulator. If the backend is not
running, start **api: MyVedicStar shared host (http://localhost:5289)** separately. Start an Android
virtual device through Android Studio's Device Manager first. Install Android SDK Platform-Tools and Android
Emulator, set `ANDROID_HOME` to the SDK directory, and add its `platform-tools` and `emulator` directories to PATH.

For a terminal-only run, start the same backend separately and set `EXPO_PUBLIC_API_BASE_URL` to
`http://10.0.2.2:5289/api/v1` before building. Authentication defaults to disabled unless `EXPO_PUBLIC_AUTH`
is configured; native sign-in requires the mobile Entra client and registered `myvedicstar://auth/callback` URI.
Use the native debug app to test OAuth redirects rather than Expo Go. iOS Simulator runs on macOS.

Native project: generated by Expo automatically when absent (git-ignored). After installation, `npm run
mobile:android` can restart Metro and open Android; use the native app when testing authentication. Press `j` in
Metro's terminal to open React Native DevTools.

Official setup: [Android virtual devices](https://developer.android.com/studio/run/managing-avds) and
[Expo authentication](https://docs.expo.dev/guides/authentication/).

## Builds (EAS)

| Profile (`apps/mobile/eas.json`) | Use                                        | Environment    |
| -------------------------------- | ------------------------------------------ | -------------- |
| `development`                    | internal testing builds                    | local API      |
| `preview`                        | internal distribution (QA)                 | staging API    |
| `production`                     | Play Store AAB, auto-increment versionCode | production API |

```bash
npx eas build --platform android --profile preview
npx eas build --platform android --profile production
npx eas submit --platform android --profile production
```

Signing: EAS-managed upload keystore (or one stored in the CI secret store). **Never commit keystores**
(`*.jks`, `*.keystore` are git-ignored). Play App Signing is enabled on the store listing.

## Mobile E2E — Maestro (recommended)

Maestro (YAML flows, no app instrumentation, works for Android emulators and iOS simulators, simple CI) is preferred
over Detox (heavier native test harness, gray-box synchronisation). Flows live in `apps/mobile/e2e/*.yaml` from
Phase 2; run on Android phone, tablet and foldable AVDs in CI where emulators are available.

## Pipeline

`.github/workflows/mobile.yml`: install → lint → typecheck → Jest tests → `expo export` (Metro bundle for Android
and iOS) → EAS build (manual trigger, requires `EXPO_TOKEN` secret) → store submission through the approved release
process.
